## 二、Claude Agent Skills — 进阶架构（2025年12月新功能）

这是 Claude 最新的、很多人还不知道的重要特性：

### Skills 是什么？

Skills = 有组织的指令/脚本/资源文件夹，**按需动态加载**。

相比传统方式把所有能力塞进一个超长 System Prompt，Skills 实现了**渐进式披露（Progressive Disclosure）**：

```
传统方式（糟糕）：
System Prompt = 角色 + 所有能力 + 所有规则 + 所有工具说明
→ 10,000+ tokens，每次都消耗，浪费且注意力稀释

Skills 方式（正确）：
System Prompt = 角色 + 行为规则（轻量）
Skills = 按需加载的能力包
→ 只有匹配的 Skill 才被加载
```

### 两级加载机制

```
Level 1（扫描阶段，极低成本）：
  Claude 只看 Skill 的名称和描述
  → 判断是否与当前请求相关

Level 2（加载阶段，只加载匹配的）：
  加载完整 SKILL.md 指令文件
  → 包含详细步骤、示例、工具配置
```

### SKILL.md 文件结构示例

```markdown
# Code Review Skill

## 触发条件
当用户要求审查代码、检查代码质量、发现Bug时使用本技能。

## 执行步骤
1. 读取代码文件（使用 filesystem 工具）
2. 按以下顺序检查：安全性 → 性能 → 可维护性
3. 对每个问题标注严重程度：P0/P1/P2
4. 生成结构化报告

## 输出格式
[严重程度] 文件:行号 — 问题描述
建议：具体修复方案

## 工具
- filesystem: 读取代码文件
- search: 查询最佳实践文档

## 示例
...
```

### 在自定义 Agent 中实现类似机制

```python
class SkillRouter:
    """
    类 Claude Skills 的轻量实现
    两级加载：先扫描名称，再加载详情
    """

    def __init__(self):
        self.skill_index = {}   # name → description（轻量）
        self.skill_detail = {}  # name → full instructions（按需加载）

    def register(self, name: str, description: str, instructions_file: str):
        self.skill_index[name] = description
        self.skill_detail[name] = instructions_file  # 只存路径，不读内容

    def match(self, task: str) -> list[str]:
        """Level 1：用 Haiku 快速匹配相关技能"""
        index_str = "\n".join(f"- {k}: {v}" for k, v in self.skill_index.items())
        response = haiku_client.generate(f"""
        从以下技能列表中，选出与任务相关的技能名称（逗号分隔，没有则返回none）：

        技能列表：
        {index_str}

        任务：{task}
        """)
        matched = [s.strip() for s in response.split(",") if s.strip() in self.skill_index]
        return matched

    def load(self, skill_names: list[str]) -> str:
        """Level 2：加载匹配技能的完整指令"""
        instructions = []
        for name in skill_names:
            if name in self.skill_detail:
                with open(self.skill_detail[name]) as f:
                    instructions.append(f"## {name}\n{f.read()}")
        return "\n\n".join(instructions)
```

## 三、上下文腐烂问题（Context Rot）——长上下文的真相

### 关键研究发现（Chroma Research, 2025）

测试 18 个 LLM 的结论：
- **模型不会均匀使用上下文**
- 随输入长度增加，性能越来越不可靠
- **大多数模型实际有效使用只有上下文的 10-20%**
- 声称 200K tokens 的模型，通常在 130K 时就开始变得不可靠

### 注意力分布规律

```
上下文位置     注意力强度
─────────────────────────
开头 (0-10%)  ████████  最高
中间 (10-90%) ██        最低（Lost in the Middle）
结尾 (90-100%)████████  次高（最近的内容）
```

**实用策略：**
```
1. 关键指令 → 放最开头
2. 用户最新问题 → 放最结尾
3. 背景/参考资料 → 放中间（注意力最弱，只放"查阅资料"而非"必须记住的规则"）
4. 在中间区域重要内容前加标记：<IMPORTANT>...</IMPORTANT>
```

### 成本分析：全文 vs 记忆系统

| 方案 | 每轮成本 | 适用场景 |
|------|---------|---------|
| 全文重发（100K tokens） | 高，每轮都付 | 短期对话，一次性任务 |
| 记忆系统（一次索引 + 检索） | 低，检索廉价 | 长期用户，频繁回访 |

**临界点：** 用户多次使用同一上下文时，记忆系统更经济。

## 四、自进化 Agent 的前沿框架（2025-2026）

### Darwin Gödel Machine（DGM）

最接近真正"自我改进"的框架：
- 维护**树状结构的 Agent 代码库存档**
- 只有在**实证上超越先祖性能**时，新代码才被接受
- 开放式进化 + 路径多样化 + 可量化安全性

```python
# DGM 核心思想的伪代码
class DarwinGodelMachine:
    def __init__(self):
        self.archive = Tree()  # 历史版本树
        self.current = BaseAgent()

    def evolve(self):
        # 1. 生成候选改进
        candidate = self.propose_improvement(self.current)

        # 2. 实证测试
        score_before = self.benchmark(self.current)
        score_after = self.benchmark(candidate)

        # 3. 只有真正更好才接受（硬性条件）
        if score_after > score_before:
            self.archive.add(self.current)  # 保存旧版本
            self.current = candidate
            return True
        return False
```

### GEPA（遗传-帕累托，OpenAI Cookbook）

可直接实现的提示词自动优化循环：
```python
def gepa_optimization_loop(agent, task_samples: list, iterations: int = 10):
    """
    遗传提示词优化
    每轮：采样轨迹 → 反思 → 提议修订 → 评估 → 保留最优
    """
    current_prompt = agent.system_prompt

    for i in range(iterations):
        # 1. 采样执行轨迹
        trajectories = [agent.run(task) for task in task_samples[:5]]

        # 2. 反思（用自然语言分析失败原因）
        reflection = reflect_on_trajectories(trajectories)

        # 3. 提议提示词修订
        revised_prompt = propose_revision(current_prompt, reflection)

        # 4. 帕累托评估（多目标）
        scores_current = evaluate(current_prompt, task_samples)
        scores_revised = evaluate(revised_prompt, task_samples)

        # 5. 只保留帕累托最优的修订
        if is_pareto_better(scores_revised, scores_current):
            current_prompt = revised_prompt
            print(f"第{i+1}轮：提示词已优化，分数 {scores_current} → {scores_revised}")

    return current_prompt
```

## 五、上下文工程 vs 提示词工程（范式转变）

Andrej Karpathy 2025 年提出的定义引发了社区广泛讨论：

### 提示词工程（旧范式）
- 关注：如何措辞
- 目标：让模型输出正确格式
- 级别：单次交互优化

### 上下文工程（新范式）
- 关注：**在上下文窗口里放什么信息**
- 目标：**用最少的 tokens 最大化期望输出概率**
- 级别：整个 Agent 系统的信息架构

```
好的上下文工程 = 找到最小的高信噪比 token 集合
                 使得下一步的期望输出概率最大化
```

### 实际操作对比

| 场景 | 提示词工程思路 | 上下文工程思路 |
|------|-------------|-------------|
| 代码库分析 | 写更好的提示词 | 动态加载相关文件，而不是全部文件 |
| 长对话 | 更清晰的指令 | 定期压缩历史，保留关键决策节点 |
| RAG | 优化 Query Rewrite | 设计"Agent 决定是否检索" |
| 多工具 | 描述工具更详细 | 技能路由，只加载相关工具文档 |

### 针对不同模型类型的上下文策略

```
推理型模型（Claude Extended Thinking, o1）：
→ 给高层目标，信任模型自行分解
→ 类比：告诉资深工程师要解决什么问题
→ 例：「实现一个高并发的消息队列，考虑各种边缘情况」

指令遵循型模型（GPT-4o, Claude Haiku）：
→ 给明确的分步指令
→ 类比：给初级工程师写任务清单
→ 例：「1.创建文件 2.添加类 3.实现方法 4.写测试」
```

```sql
-- PostgreSQL + pgvector 一体化示例
CREATE EXTENSION IF NOT EXISTS vector;

-- 知识库表
CREATE TABLE knowledge_items (
    id SERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding vector(1536),  -- OpenAI/Claude 嵌入维度
    metadata JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 向量相似度搜索
SELECT content, 1 - (embedding <=> $1::vector) AS similarity
FROM knowledge_items
ORDER BY embedding <=> $1::vector
LIMIT 5;

-- 组合向量搜索 + 全文搜索（混合搜索）
SELECT content
FROM knowledge_items
WHERE
  to_tsvector('chinese', content) @@ plainto_tsquery('chinese', $2)
  OR (embedding <=> $1::vector) < 0.3
ORDER BY (embedding <=> $1::vector) + ts_rank(...) DESC
LIMIT 10;
```

## 九、ReAct 框架的标准实现

很多教程讲 ReAct 但没有完整代码，这里给出完整实现：

```python
class ReActAgent:
    """
    Reason + Act 框架
    思考-行动-观察 循环
    """

    SYSTEM_PROMPT = """
    你是一个使用 ReAct 框架的智能助手。

    每一步你都需要按以下格式思考和行动：

    Thought: [你对当前情况的分析和下一步计划]
    Action: [工具名称]
    Action Input: [工具的输入参数（JSON格式）]

    收到工具结果后：
    Observation: [工具返回的结果]
    Thought: [基于结果的新分析]
    ... (继续循环)

    当你有足够信息给出最终答案时：
    Thought: 我现在可以回答了
    Final Answer: [最终答案]

    可用工具：
    {tools_description}
    """

    def __init__(self, tools: dict):
        self.tools = tools
        self.client = anthropic.Anthropic()

    def run(self, question: str, max_steps: int = 10) -> str:
        tools_desc = "\n".join(f"- {name}: {fn.__doc__}"
                               for name, fn in self.tools.items())

        messages = [{"role": "user", "content": question}]
        system = self.SYSTEM_PROMPT.format(tools_description=tools_desc)

        for step in range(max_steps):
            response = self.client.messages.create(
                model="claude-haiku-4-5-20251001",
                max_tokens=1000,
                system=system,
                messages=messages,
                stop_sequences=["Observation:"]
            )

            output = response.content[0].text
            messages.append({"role": "assistant", "content": output})

            # 解析最终答案
            if "Final Answer:" in output:
                return output.split("Final Answer:")[-1].strip()

            # 解析并执行工具调用
            if "Action:" in output:
                lines = output.strip().split("\n")
                action = None
                action_input = None

                for i, line in enumerate(lines):
                    if line.startswith("Action:"):
                        action = line.replace("Action:", "").strip()
                    if line.startswith("Action Input:"):
                        try:
                            action_input = json.loads(
                                line.replace("Action Input:", "").strip()
                            )
                        except:
                            action_input = {"input": line.replace("Action Input:", "").strip()}

                if action and action in self.tools:
                    try:
                        result = self.tools[action](**action_input)
                        observation = f"Observation: {result}\n"
                    except Exception as e:
                        observation = f"Observation: 工具执行失败 - {str(e)}\n"
                else:
                    observation = f"Observation: 工具 '{action}' 不存在\n"

                messages.append({"role": "user", "content": observation})

        return "达到最大步骤数，无法完成任务"
```
